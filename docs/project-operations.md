# 里程碑与外部验收

产品负责人或管理员可以为已冻结基线登记交付日期、生产环境和责任人。研发期间可先创建里程碑，待制品和用例准备后关联候选。调整计划会保留原基线、候选和截止日。生产执行开始后锁定交付目标，签收后同时锁定计划日期。

## 查看周期与阻断

工作台根据候选和生产状态显示当前环节。可在里程碑下打开基线、候选、部署、验收记录和时间线。对于结果待核实的部署，先按原请求键向执行工具查单。生产已成功但报告未归档时，里程碑显示「等待业务签收」，并列出待处理标准和当前签收人。

| 周期 | 计算边界 |
| --- | --- |
| 开发 | 基线冻结至候选登记 |
| 等待测试 | 候选登记至开启候选测试 |
| 测试执行 | 开启候选测试至首次进入审批 |
| 等待审批 | 首次进入审批至记录有效审批 |
| 等待上线 | 批准至目标生产环境确认成功 |
| 等待业务签收 | 该环境确认成功至报告归档，或未归档时首次被后续部署取代 |

周期按 UTC 时间戳得到墙钟时长。运行中的周期计算到查看或快照时刻。遇到重新测试或重新审批时，后续动作可在候选时间线查看。保存周期快照后，即使当前里程碑签收或调整计划，已保存结果仍可查阅。

产品负责人或管理员可移交里程碑和研发任务。研发任务移交后由新责任人重新认领，旧认领人、认领时间、提交绑定和移交原因仍可回查。

## 给外部验收人授权

1. 由管理员创建「外部验收人」账号。对方登录后进入外部交付包页面。
2. 产品负责人在已归档报告点击「用此报告生成外部交付包」，勾选可分享的标准并保存。外部包固定所选标准、发布版本、结论和补验截止日。
3. 核对包内项目可披露的标题与验收条件。填写外部验收人账号和过期日，授予对该包的访问权限。
4. 对方可在线阅读和下载 JSON。授权到期或被撤回后，列表及下载接口立即按当前授权判断。归档证据、项目任务、仓库、内部意见和原始测试回执可在内部工作台按权限查阅。

过期日按 UTC 自然日计算，当天仍有效。重新授权会留下新审计事件，原有事件可从交付包时间线查看。

## HTTP 接口

| 路径 | 操作 |
| --- | --- |
| `/api/projects/{project}/milestones` | 列表和创建 |
| `/api/projects/{project}/milestones/{id}` | 详情和计划更新 |
| `/api/projects/{project}/milestones/{id}/metrics` | 周期快照列表和保存 |
| `/api/projects/{project}/milestones/{id}/ownership` | 移交记录和变更 |
| `/api/projects/{project}/work-items/{id}/ownership` | 任务移交记录和变更 |
| `/api/projects/{project}/review-packages` | 列表和打包 |
| `/api/projects/{project}/review-packages/{id}/grants` | 访问授权列表 |
| `/api/projects/{project}/review-packages/{id}/grants/{reviewer}` | 更新授权 |
| `/api/projects/{project}/review-packages/{id}/grants/{reviewer}/revoke` | 撤回授权 |
| `/api/review-packages` | 外部验收人的授权列表 |
| `/api/review-packages/{id}/content` | 外部包 JSON 下载 |

里程碑和交付包详情均有 `/timeline` 端点。内部更新使用会话 CSRF 头。计划更新携带当前 `version`，字段 `candidate_id` 传空值可在部署开始前解除关联。移交请求携带 `expected_owner_id`、`next_owner_id` 和 `reason`。

AC-15 和 AC-16 由 `tests/deployments_http.py` 驱动，验证实际生产确认后仍等待业务签收时的逾期归因，以及账号、租户、交付包、下载和撤回之间的权限边界。
