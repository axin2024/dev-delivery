# 企业研发协作与交付管理平台 2.0 产品需求文档

**软件发布列车与生产变更治理**
需求评审版 · 2026-11-26 · 计划基线 v1.1.0（59c7273）

## 产品目标与交付边界

当前发行覆盖项目基线、迭代、交付证据与签收。本版支持以下业务流程。发布经理将多个服务装入同一列车，在预演、变更窗口和分批放量期间收集证据，到点选择推进或恢复。 [现有项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

首期接入声明式部署适配器和回环模拟环境。手工接管也必须回填目标、执行摘要和外部回执。

## 使用者与工作台

发布经理封板，服务负责人签制品，环境管理员授权执行，值班人员有暂停权。

列车看板左侧为依赖顺序，右侧显示每环境实际制品与最近观测。暂停时值班人员可展开受影响节点、最后一次成功操作及恢复方案。

## 功能需求

下列六项均纳入正式版本。验收编号按项目独立，后文列出每项的触发条件和预期结果。

| 需求 | 模块 | 产品行为与约束 | 验收 |
| --- | --- | --- | --- |
| R1 | 服务目录 | 登记服务负责人及上游依赖，关联制品摘要，按依赖图推导发布顺序。 | A1、A2 |
| R2 | 列车编排 | 选择冻结基线、协调共享窗口、封板后通过修订替换单个组件。 | A3、A4 |
| R3 | 预演与签核 | 在预发执行迁移和健康探针，记录批准身份、制品版本与有效期。 | A5、A6 |
| R4 | 分批执行 | 按区域和比例推进，保存每波实际节点，暂停后按原清单恢复。 | A7、A8 |
| R5 | 质量判定 | 定义最小样本及错误率，拼接变更前后观测窗口，人工豁免须给原因和截止时间。 | A9、A10 |
| R6 | 恢复与复盘 | 按依赖倒序恢复兼容版本，为单向迁移选择前向修复，生成实际时间线。 | A11、A12 |

## 页面操作与回执

| 关联需求 | 角色与入口 | 操作细节 | 需要读回的字段 |
| --- | --- | --- | --- |
| R1 · 服务目录 | 服务负责人/依赖图 | 登记提供与消费关系，核实每个组件的制品摘要 | service_id、digest |
| R2 · 列车编排 | 发布经理/列车日历 | 选窗口、锁目标环境，封板后发起清单变更 | train_rev、window_id |
| R3 · 预演与签核 | 环境负责人/预演台 | 按目标制品执行验证并签认可复查的环境快照 | environment_rev、approval_id |
| R4 · 分批执行 | 值班工程师/分波执行 | 展开每波节点实况，按同一选择集恢复执行 | wave_id、actual_targets |
| R5 · 质量判定 | 质量负责人/指标窗口 | 对照最小样本和误差阈值，给出暂停或放行原因 | observation_id、decision |
| R6 · 恢复与复盘 | 生产负责人/恢复台 | 校验旧制品兼容性并按实际部署目标执行恢复 | recovery_id、verified_digest |

预演适配器至少支持读当前版本、应用目标、查执行结果及恢复旧版四类操作。真实生产演示可由自托管测试环境充当，发布样例记录各节点原始摘要。

## 状态、权限与数据

列车 草案→封板→预演通过→批准→逐波执行→完成。暂停后可继续原波、恢复或前向修复。

阈值按窗口内错误请求数除总请求数计算，豁免不能跨制品版本。恢复动作保留重复执行身份。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `release_train(window,owner)`
- `component_pin(repo,commit,digest)`
- `rollout_wave(region,threshold)`
- `observation(sample_count,error_count)`
- `rollback_receipt(target,digest)`

执行记录按环境、列车修订、波次和目标唯一，观测引用实际部署而非计划时间。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /release-trains/{id}/waves/{wave}/advance`。请求必填字段为 `revision, observation_id, approval_id`。成功回执提供 execution_id, pinned_targets, state。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "revision": 4,
  "observation_id": "M8",
  "approval_id": "A3"
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "execution_id": "X2",
  "pinned_targets": [
    "node-02",
    "node-03"
  ],
  "state": "accepted"
}
```

审批绑定旧制品时返回 409，发布人可查看新旧摘要并重新申请批准。

## 升级、部署与恢复

既有交付基线只读关联到列车。生产环境及可执行连接器由环境负责人逐项授权。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对发布制品摘要、环境回执及审批记录。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

| A3 | R2 · 列车编排 | 两组件不同仓库提交可生成一份可下载清单。 |

| A6 | R3 · 预演与签核 | 更换一个制品使该组件审批过期。 |
| A7 | R4 · 分批执行 | 1、4、5 台三波发布最终覆盖 10 台且不重复执行。 |

负载报告须记录机器及依赖版本、预热和采样时长、成功数、拒绝数和超时数。验收人从工作台与业务记录两侧核对 A13，并附上原始输入、回执和最终状态。

运行报告可按 trace ID 关联适配器调用、观测采集与恢复步骤，保留每一步的调用时段和结果。[OpenTelemetry 调用链说明](https://opentelemetry.io/docs/concepts/signals/traces/)

### A13 故障位置

测试适配器先持久化节点制品摘要，再主动中断响应。恢复进程读取执行号、目标节点与实际摘要后决定是否重发，验收须对比适配器的实际执行计数。

## 分期交付

1. **服务与制品目录。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **预演和分波生产适配器。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **恢复、观测与复盘。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
