# 企业研发协作与交付管理平台｜验收与运营

## 前置条件

在独立 MySQL 中导入可重置样例并创建两组隔离身份。演示资源包括原创需求、两套合成构建记录、测试 XML 和签收角色。冻结版本、输入、机器和时钟设置，接口回放与真实依赖的结果分列。

## 综合验收

**输入**　B1 含 C1、C2，版本候选 R1 绑定制品 H1；业务修订 C2，开发产生 H2，并收到 H1 的迟到成功回执。

**通过条件**　R1 保留旧证据，C2 的测试需在 H2 上重新通过；C1 可引用有效需求证据，涉及构建行为的门禁仍须满足 H2 的要求。

在提交成功和回执返回之间断开，再使用相同标识重试。验收人同时检查 MySQL、界面和外部回执，记录业务结果数、重试次数及仍待人工处理的对象。用其他租户重复查询、下载和导出，预期可见记录为零。

## 容量与可观测性

1 万任务的迭代面板 p95 目标 2 秒；错绑提交、错误环境和过期候选的发布成功数为零。 附测量持续时间、负载构成、热身与稳定窗口、资源上限和异常分类。演练前后的持久记录须能关联到同一个请求或运行。
