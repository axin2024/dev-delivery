# 业务签收与交付报告

项目指定的业务签收人在工作台打开当前生产部署，按冻结基线逐项记录业务结论。项目成员可以查看结论历史、生产晋级链和报告。每次签收均关联到具体生产部署，同一候选如果发布到多个生产环境，需要分别签收。

## 逐项验收

1. 在「业务签收和交付报告」选择对应生产部署，核对候选版本、环境和验收标准。不同需求可以分别筛选。
2. 填写业务结论和依据。通过项直接满足归档条件，阻断项需重新验收通过或由签收人签署豁免。
3. 签署豁免时填写理由、项目内补验负责人和补验截止日。截止日按 UTC 自然日计算，当天仍有效。到期未归档的豁免须重新判定。
4. 打开追溯矩阵核对证据。所有标准已通过或具备有效豁免时，签收人可归档。报告归档后可下载 JSON 和校验 SHA-256。

结论按次追加，保留实际操作者、姓名、时间、标准版和理由。页面提交时带最近一次结论 ID，便于在多个签收窗口同时修改时重新核对。生产环境换版或回滚后，旧部署仍可查看及下载已归档报告，未归档的旧部署停止接收结论。回滚动作由部署时间线记录。

## 追溯矩阵

矩阵按需求和标准版本展开，包含冻结的需求快照、研发任务、已绑定的提交、发布候选清单、制品摘要、构建运行号、审批引用的测试结果、关联缺陷的失败及复测证据、部署工具回执和签收结论。任务关联提交会标明是否与部署制品使用的构建提交一致。没有任务或提交关联时，工作台会提示。

上线后的补充跑测继续进入测试时间线。交付报告按生产部署所记录的门禁摘要取回当次审批与结果。报告预览和归档都按相同规则生成 SHA-256，归档会核对签收进度、环境生效版本和预览摘要。报告采用 UTF-8 JSON，单份归档上限 8 MiB。

## HTTP 接口

下列路径均位于 `/api/projects/{project}/signoffs`，写入使用会话 CSRF 头。

| 方法与路径 | 用途 |
| --- | --- |
| `GET` 根路径 | 按部署 ID 游标查看已有的生产晋级 |
| `GET /{deployment}` | 查看归档状态和逐项签收 |
| `GET /{deployment}/criteria/{criterion}` | 分页查看逐项结论历史 |
| `PUT /{deployment}/criteria/{criterion}` | 追加绑定标准版的结论 |
| `GET /{deployment}/timeline` | 查看实际签收和归档动作 |
| `GET /{deployment}/report-preview` | 查看追溯矩阵和 SHA-256 |
| `POST /{deployment}/report` | 按预览 SHA-256 归档 |
| `GET /{deployment}/report` | 下载原始归档 JSON 文件 |

提交结论填写 `revision_id`、`decision` 和 `note`。已有结论时填写 `expected_decision_id`，首次传空值。结论为 `waived` 时同时填写 `responsible_id` 和 `retest_due_on`。归档请求填写 `digest`。对同一摘要重试归档会返回原报告元数据。

## 验收

`tests/deployments_http.py` 驱动两个 PHP HTTP 进程和 MySQL 中的数据，调用 `tests/signoffs_http.py` 验证 AC-13 与 AC-14。验收从候选生产晋级执行到签收，包含实际的本地 Git 提交、隔离成员和制品字节。用例会验证部署后的测试记录变化、旧部署写入限制、阻断归档、具名豁免、并发归档、报告字节摘要、变更影响关联及回滚后的历史查阅。
