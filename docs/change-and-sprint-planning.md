# 变更评审和迭代排期

## 冻结后的验收标准

1. 产品负责人在工作台打开最新基线，按标准版本创建研发任务与关联用例。
2. 在「变更评审」中发起变更，选中需要调整的条款并填写新的验收条件和理由。单张变更单可以包含多条修订。
3. 业务签收人核对原条件、新条件、关联任务、用例和缺口，再批准或驳回。批准后，受影响的任务和用例带上待重新确认标记，原基线和原条款版本仍可打开。
4. 产品负责人核对修订后的范围并冻结后续基线。对已过期版本提交审批时，系统返回当前版本供重新核对。

已完成的变更保存决策时的影响清单，供审计复核。业务签收记录接入交付包后会纳入影响清单，当前开发版本将该关联显示为缺口。

## 团队容量和依赖

团队用编码标识，每个迭代登记起止日期和总工作点数。打开任务后可以安排到所属团队的迭代，工作台显示已分配点数和总容量。并发写入在项目事务内校验容量。

依赖记录前置任务、责任人和交接日。待排期时可以录入互相依赖的任务，工作台会显示循环路径。须删除循环边才能排期。下游已排期的情况下，前置迭代须在下游迭代开始和交接日两者中较早的日期前完成。冲突回执给出关联任务及受影响迭代。

## API

以下路径以 `/api/projects/{project}` 开头。列表的查询参数 `after` 对应响应中的 `next_after`。

| 路径 | 操作 |
| --- | --- |
| `/changes` | 查询或提交变更 |
| `/changes/{change}/decision` | 业务签收人确认批准或驳回 |
| `/changes/{change}/timeline` | 读取变更对象时间线 |
| `/sprints` | 查询或创建迭代 |
| `/sprints/{sprint}` | 读取容量和迭代任务 |
| `/work-items` | 查询或创建任务 |
| `/work-items/{item}/schedule` | 安排迭代，`sprint_id` 为 `null` 时取消 |
| `/work-items/{item}/dependencies/{predecessor}` | 保存或删除前置依赖 |
| `/work-items/{item}/timeline` | 读取任务时间线 |
| `/test-cases` | 查询或登记关联用例 |

## 验收

在专用 `delivery_test_*` 数据库配置完成后，可使用两个指向同一数据库的 PHP HTTP 实例运行下面的测试。

```sh
python tests/baselines_http.py http://127.0.0.1:8080 http://127.0.0.1:8081
python tests/planning_http.py http://127.0.0.1:8080 http://127.0.0.1:8081
```

测试覆盖 C2 选择性标记、关联缺口、审批幂等、旧基线复原、跨租户访问拦截、循环依赖、容量竞争和冲突排期回滚。
