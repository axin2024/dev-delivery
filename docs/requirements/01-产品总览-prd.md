# 企业研发协作与交付管理平台｜产品总览

**正式需求基线 v2 · PHP · 独立开源项目**

统一需求、构建、发布和签收证据。代码托管和部署由连接器提供回执，平台支持离线导入。

## 使用者与责任边界

产品经理定基线，工程师关联提交，测试人员复测，发布经理管理环境，业务代表签收授权范围。

## 完整交付链路

项目与需求基线 → 变更与迭代 → 研发协作 → 测试与缺陷 → 候选与制品 → 发布与回滚 → 验收与交付 → 项目运营。

## 产品范围与里程碑

| 里程碑 | 能力 | 交付物或判断依据 |
|---|---|---|
| 基础数据与首笔业务 | 项目与需求基线、变更与迭代 | 标准 C2 变化只标记关联任务及用例。 |
| 贯通核心生产流程 | 研发协作、测试与缺陷、候选与制品 | 正式版与热修版可同时评审。 |
| 异常、运营与独立交付 | 发布与回滚、验收与交付、项目运营 | 延误定位到等待业务签收而非开发阶段。 |

里程碑用于排开发顺序。首个完整公开版包含本项目全部 8 个业务域、24 项细分能力以及验收表的全部编号场景。

## 公开演示与成效

B1 含 C1、C2，版本候选 R1 绑定制品 H1；业务修订 C2，开发产生 H2，并收到 H1 的迟到成功回执。

R1 保留旧证据，C2 的测试需在 H2 上重新通过；C1 可引用有效需求证据，涉及构建行为的门禁仍须满足 H2 的要求。

1 万任务的迭代面板 p95 目标 2 秒；错绑提交、错误环境和过期候选的发布成功数为零。以上为发布目标，验收报告须给出实测环境及原始记录。

## 边界与外部依据

缺测试覆盖与测试失败分别展示；紧急豁免写明签署人、理由、受影响标准和补验期限。

接口和业务术语的参考材料见 [GitHub Checks](https://docs.github.com/en/rest/checks/runs)。具体范围由本项目的操作契约与验收用例界定。
