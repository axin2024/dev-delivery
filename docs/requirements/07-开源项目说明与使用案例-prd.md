# 企业研发协作与交付管理平台｜开源项目说明与首个案例

**dev-delivery** 是面向自托管的 PHP 项目。统一需求、构建、发布和签收证据。代码托管和部署由连接器提供回执，平台支持离线导入。 本页作为后续公开使用手册的需求稿，实际发行时补入测试版本、安装入口与已验证的依赖组合。

## 准备

原创需求、两套合成构建记录、测试 XML 和签收角色。

B1 含 C1、C2，版本候选 R1 绑定制品 H1；业务修订 C2，开发产生 H2，并收到 H1 的迟到成功回执。

## 第一次使用

1. 产品经理发布 B1，登记 C1、C2 和各自关联测试；测试人员录入 H1 制品及通过回执。
2. 冻结 R1 后提交 C2 变更，由测试负责人检查受影响任务、用例和失效门禁。
3. 建立 R2 与 H2，投递 H1 的迟到成功回执，观察 R2 的门禁仍待复测。
4. 在 H2 上通过必测项，完成生产审批和业务签收，沿 R2 报告点回修订标准与测试证据。

## 对照综合样例

R1 保留旧证据，C2 的测试需在 H2 上重新通过；C1 可引用有效需求证据，涉及构建行为的门禁仍须满足 H2 的要求。 对照结果时保留源记录号、版本和操作时间，追踪从输入到最终交付的关联。

## 制造一次可恢复的异常

替换制品后撤销旧批准，要求重新核验。回到对象详情核对 candidate 和审计记录，再按指定版本恢复或重试。确认相同操作不会生成两份有效结果。

## 自托管与反馈

缺测试覆盖与测试失败分别展示；紧急豁免写明签署人、理由、受影响标准和补验期限。 提交问题请提供版本、最小合成输入、预期与实际结果。对接扩展可从以下方向开始：代码托管、CI、发布回执与报告扩展；提交合成事件和迟到回执测试向量。
